# 研究计划：NessRC 高保真自定义赛道编辑器

## 研究目标

找出一套能在 `www.nessrc.net` 中落地、让普通用户较低门槛地设计出接近 NessRC 实际赛道图的技术方案。研究不只比较“画图编辑器”，而是同时解决：

1. 如何用合适的数据模型表达真实赛道的中心线、边界、宽度、弯道、路缘和开放/闭合拓扑。
2. 如何让用户通过拖拽、模板、草图、参考图或参数生成，得到自然且可控的赛道。
3. 如何自动阻止自交、过窄、急弯、越界、不可制造等无效设计。
4. 如何从现有商品图/设计稿中提取可复用模板与几何参数。
5. 哪些开源项目、算法和论文可以直接复用，哪些只能提供思路，哪些需要自主实现。
6. 如何分阶段替换现有实现，并兼容当前订单中的 `custom_track_design` 数据。

最终研究应给出明确推荐，而不是罗列链接：包括推荐的数据模型、几何内核、交互方式、开源依赖、自动生成方法、迁移路径、原型验收标准和风险。

## 发现的项目上下文

### 相关项目

- 商城与自定义设计器：`nesstrack-store`，线上对应 `www.nessrc.net`。
- 工厂/订单后台：外层 `Nesstrack` 仓库；本研究以商城设计器为主，同时检查输出如何被订单及供应商环节消费。
- 技术栈：Next.js 16.2.1、React 19、TypeScript、SVG 渲染、Supabase 存储订单设计 JSON 与预览图。

### 当前实现基线

- `app/customize/page.tsx`：尺寸 → 模板 → 编辑三步流程。
- `components/track-design/TrackEditor.tsx`：增加、拖动、删除锚点，开环/闭环，撤销/重做。
- `components/track-design/EditorCanvas.tsx`：SVG 画布、标尺、锚点拖拽。
- `components/track-design/EditorSidebar.tsx`：全局/局部宽度和锚点圆角半径。
- `lib/track-design/types.ts`：当前 V1 模型为折线锚点 + 每点圆角 + 每点宽度。
- `lib/track-design/geometry.ts`：直线段加圆弧 fillet 的中心线模型。
- `lib/track-design/ribbon.ts`：中心线采样、法线偏移、可变宽 ribbon、简单折叠修正与路缘段。
- `lib/track-design/bounds.ts`：画布边界检查，但尚未构成完整的几何合法性/制造约束系统。
- `lib/track-design/templates.ts`：12 个手工模板，部分参考实际商品赛道。
- `tools/trace_thumbnails.py`：OpenCV + scikit-image skeletonize + NetworkX + Douglas–Peucker 的商品缩略图中心线提取实验。
- `lib/tracks.ts`：118 条商品赛道目录，可作为真实赛道样本索引。
- `tools/trace_output/cache/`：当前已缓存 12 张代表性商品图；`templates.json` 和 debug 图可作为已有实验材料。

### 当前已知能力缺口（研究中需逐项验证）

- 当前中心线由“直线 + 定半径圆角”组成，难以表达连续、自然的复合弯、S 弯、渐变曲率和精确切线。
- 缺少 Bézier/B-spline/NURBS/Clothoid 等高级曲线控制方式，也没有曲率连续性指标。
- 可变宽度只附着在锚点并沿段插值，缺少独立宽度剖面、左右边界分别编辑及局部拓宽语义。
- 路缘由“小半径弧”启发式推断，不能表达只在弯内侧、指定区间、不同颜色/节奏/宽度的真实路缘。
- 没有可靠的自交检测、最小净距、中心线与边界碰撞、内外偏移奇异点、闭环方向和拓扑验证。
- 没有吸附、切线手柄、对称、镜像、旋转缩放、分段选择、多点变形、节点插入、平滑/简化等成熟编辑操作。
- 缩略图自动提取依赖颜色阈值和骨架化，容易受背景、阴影、纹理、路缘、透视与分支毛刺影响。
- 当前模板是人工近似，尚无针对“与真实赛道有多接近”的定量基准。
- 缺少可制造约束、成本/面积/长度联动以及生产级矢量导出规范。
- V1 JSON 缺少显式 segment 类型、切线、左右宽度、装饰区间、约束与生成来源等字段。

### 现有研究/笔记

- 仓库内未发现现成的系统性研究文档。
- 已有代码、测试、提交历史和 `trace_thumbnails.py` 属于早期实现证据，将纳入基线审计，避免重复探索。

## 研究边界与关键问题

### 必须回答

1. NessRC 实际赛道图的视觉和几何规律是什么，哪些细节决定“像真赛道”？
2. 中心线建模、双边界建模、模块拼装三种范式中，哪一种最适合当前产品，是否需要混合模型？
3. 真实商品中是否存在交叉、桥接、开放赛道、多车道、分叉或非恒定宽度等特殊拓扑？
4. 设计器应面向普通买家还是专业设计人员；如何同时提供简单模式与高级模式？
5. 哪些算法适合浏览器实时运行，哪些应放到服务端/WASM/Python 离线管线？
6. 生成式 AI 是否能稳定输出可编辑、合法、可制造的几何，还是只适合作为草图/候选生成器？
7. 现有 V1 订单数据如何无损迁移或继续渲染？
8. 最小可用升级与最终高保真版本分别需要多大工作量和技术风险？

### 暂不默认包含

- 不在研究阶段直接改生产代码或数据库。
- 不把纯视觉上相似但无法转成可制造几何的图片生成当成完成方案。
- 不预设必须使用某个画布框架；先确定几何内核和数据模型，再比较 UI 框架。

## 样本分析计划：从真实赛道反推需求

### 1. 建立样本集

- 从 118 条 `lib/tracks.ts` 商品中按尺寸、横竖比例、开/闭环、弯道数量、拓扑复杂度分层抽样。
- 第一批至少覆盖当前缓存/手工模板对应的 `track-3/15/25/35/45/50/60/70/80/90/100/110`。
- 如仓库外存在源设计稿、高清平面图、生产矢量文件或现场照片，执行阶段应补入并标注来源；缩略图不能替代生产原稿。
- 为每个样本保存：原图、标注图、尺寸、可信度、提取中心线、左右边界、装饰层和异常说明。

### 2. 建立真实赛道特征表

逐图标注并统计：

- 拓扑：闭环/开环、环数、交叉/接近交叉、分支、窄颈、发夹弯、S 弯、回转、长直道。
- 中心线：节点数量、弧长、切线方向、曲率分布、曲率突变、最小转弯半径、直线/缓和曲线/圆弧比例。
- 宽度：平均、最小、最大宽度；左右是否对称；弯道局部扩宽；宽度变化速度。
- 边界：是否为中心线等距偏移、边缘是否独立变形、闭环内外边界关系、端帽形状。
- 装饰：路缘出现位置、内/外侧、长度、条纹节奏、颜色、中线、起终点线、Logo/安全区等。
- 版面：赛道占画布比例、边距、方向、重心、负空间、尺寸适配方式。
- 制造：最小间距、最小特征尺寸、切割/印刷出血、允许的尖角与自交、文件输出要求。

### 3. 建立“相似度”和合法性基准

- 几何相似：Chamfer/Hausdorff 距离、轮廓 IoU、中心线 Fréchet/DTW、长度误差、曲率分布误差。
- 视觉相似：统一渲染后的像素 IoU/SSIM，仅作为辅助，避免背景风格掩盖几何问题。
- 拓扑相似：闭合状态、连通分量、环/分支/交叉数量必须一致。
- 设计质量：自交数、边界交叉、最小净距、越界量、曲率连续性、最大曲率、宽度梯度。
- 可编辑性：达到目标形状所需操作数、耗时、撤销次数、错误率，以及用户是否能理解控制点。

## 当前功能审计计划

### 数据模型审计

- 逐字段分析 V1 `TrackDesign` 的表达上限及兼容约束。
- 构造当前模型难以表达的真实赛道反例。
- 比较 V2 候选：分段曲线图、中心线 + width profile、左右独立边界、模块图、混合模型。
- 设计版本化、序列化、迁移、校验、预览、订单与后台消费契约。

### 几何内核审计

- 验证 fillet、ribbon sampling、法线偏移、宽度钳制在急弯、S 弯、发夹弯、短段和闭环接缝下的稳定性。
- 检查采样密度依赖、偏移折叠、尖角、miter/round join、数值误差与性能。
- 建立最小测试图集，记录当前输出失败类型和复现数据。

### 编辑交互审计

- 按“从空白创建”“套模板改形”“参考图描摹”“导入已有设计”四条任务流审计。
- 桌面鼠标与移动触控分别检查选点、拖拽、插点、删点、缩放/平移、精细控制、错误恢复和尺寸反馈。
- 记录现有交互中用户必须理解的几何概念，评估哪些应自动化或放入高级模式。

### 生产链路审计

- 追踪从设计 JSON、预览 PNG、订单写入到后台/供应商展示及最终生产文件的全链路。
- 查明价格需要面积、外框、赛道长度还是其他几何量，并在 V2 模型中保留可确定计算。
- 确定 SVG/PDF/DXF/高分辨率 PNG 等实际导出需求与单位、DPI、色彩、出血规范。

## 候选技术路线

每条路线都要从表达力、易用性、稳定性、浏览器性能、开源成熟度、许可证、维护成本、可制造性和 V1 迁移难度进行比较。

### 路线 A：矢量路径/样条编辑器

- 比较 cubic Bézier、Catmull–Rom、B-spline、NURBS、biarc、Euler spiral/clothoid。
- 研究 G0/G1/G2 连续性、自动平滑、切线手柄、曲率约束、路径重采样和弧长参数化。
- 研究 SVG/Canvas/WebGL 编辑框架与独立几何库的职责边界。
- 重点判断：以中心线为主、生成左右边界是否足以复现真实产品。

### 路线 B：道路/赛道专用生成与几何算法

- 调研道路几何、赛车赛道生成、游戏道路编辑器、OpenDRIVE/道路网络、地图制图等相关开源项目。
- 重点研究 offset curve/buffer、parallel curve、sweep、variable-width stroke、straight skeleton/medial axis、curve fitting、self-intersection cleanup。
- 研究发夹弯、S 弯、缓和曲线、局部扩宽、路缘区间和起终点等领域语义。
- 判断是否需要采用道路 segment 图模型，而不是通用 SVG path。

### 路线 C：程序化生成

- 参数化原语：直道、圆弧、S 弯、发夹弯、chicane、loop/lobe 等模块组合。
- 生成方法：随机游走、Voronoi/Delaunay、样条闭环、L-system/shape grammar、模板变形、模块拼装。
- 控制条件：目标画布、长度、复杂度、弯道数量、最小半径、风格、开放/闭合。
- 比较“生成多个合法候选供选择”与“实时随参数变形”的用户体验。

### 路线 D：约束优化与自动修复

- 将越界、自交、最小净距、最小半径、最大曲率、曲率变化、目标长度、画布利用率、对称/风格作为硬/软约束。
- 调研非线性优化、序列二次规划、梯度/无梯度优化、CMA-ES/遗传算法、模拟退火、可微曲线拟合等方案。
- 研究局部修复：拖动时投影到可行域、自动平滑、碰撞排斥、约束求解后回弹。
- 给出实时浏览器、Web Worker/WASM、服务端三种运行位置的性能分界。

### 路线 E：图像分割、骨架化与矢量化

- 以现有 `trace_thumbnails.py` 为基线，比较颜色阈值、语义分割、轮廓提取、distance transform、skeleton/medial axis、图清理、中心线排序、曲线拟合。
- 研究从单张平面图同时恢复中心线、左右边界、宽度剖面、装饰层和画布尺度。
- 处理背景纹理、阴影、路缘误分割、断裂、伪分支、透视、低分辨率等问题。
- 区分“批量把现有 118 条商品变为模板”的离线管线和“用户上传图片即时描摹”的在线能力。

### 路线 F：生成式 AI

- 研究文字 → 赛道、草图/参考图 → 矢量、图像 → 结构化几何三类用途。
- 比较通用多模态模型、矢量生成模型、扩散模型 + 控制条件、神经隐式曲线/布局模型。
- 强制输出经过确定性几何解析器和约束校验，不能直接把生成图片作为生产文件。
- 评估稳定性、可重复性、成本、延迟、隐私、版权、供应商锁定和失败回退。

### 路线 G：混合产品方案

- 假设候选：模板/程序生成提供合法初稿，样条编辑完成精修，约束求解实时护栏，图片矢量化负责导入，AI 只负责提出候选或解释用户意图。
- 比较简单模式（风格/复杂度/尺寸滑块）和高级模式（节点/切线/宽度/装饰分段）的双层交互。
- 研究是否保留旧 V1 renderer 作为兼容层，并以 V2 几何内核承接新设计。

### 开源筛选标准

对每个候选建立统一评分卡：

1. **功能匹配**：是否真正支持闭环、样条、可变宽、offset、自交处理、曲率/约束，而非仅能显示 SVG。
2. **输出可控**：是否可访问和持久化完整几何数据，能否生成确定性 SVG/生产文件。
3. **成熟度**：最近提交、发布频率、issue 响应、测试覆盖、文档、真实使用案例、维护者数量。
4. **许可证**：优先 MIT/BSD/Apache-2.0；GPL/AGPL/SSPL 或自定义限制必须单独评估商业使用和前端分发影响。
5. **集成成本**：TypeScript/JavaScript 原生优先；Rust/C++ 需评估 WASM 体积、构建链和调试成本；Python 更适合离线/服务端。
6. **性能**：目标规模下编辑延迟、内存、首次加载、移动端表现、Web Worker/WASM 可行性。
7. **几何鲁棒性**：退化线段、极小半径、闭环接缝、宽度突变、自交、数值精度和错误恢复。
8. **可扩展性**：能否加入宽度剖面、路缘语义、约束、导出、协作历史和 V2 schema。
9. **依赖风险**：传递依赖、供应链、包体、维护权、API 稳定性和浏览器兼容。
10. **证据等级**：运行示例/测试 > 源码审计 > 官方文档 > README 声称 > 二手文章。

### 候选淘汰规则

- 无明确商业可用许可证。
- 只能生成位图，无法得到结构化可编辑几何。
- 依赖远程闭源服务且无可靠导出/回退。
- 关键几何运算在真实样本上频繁崩溃、自交或产生不可制造轮廓。
- 项目长期失维护且无可控的小型核心可 fork。

## 方案验证方法

### 1. 统一测试语料

- 真实赛道代表集：至少 20 个，覆盖简单椭圆、长直道、复杂闭环、发夹、S 弯、窄颈、可变宽和开放路径。
- 人工压力集：短段、重合点、极尖角、近自交、实际自交、宽度大于曲率半径、贴边闭环和超多节点。
- 用户任务集：空白创建、模板修改、图片描摹、文字/参数生成、旧设计打开与再次保存。

### 2. 候选最小原型（spike）

- 每个入围路线只实现同一组核心任务：载入基准 JSON、编辑 3 个关键弯、局部改宽、合法性检查、SVG 导出。
- 所有原型输出统一中间格式，避免 UI 美观度干扰几何比较。
- 对关键库必须运行其源码/示例并记录版本、许可证、构建方式和失败样例，不只引用 README。

### 3. 定量验收指标

- 真实样本重建：轮廓 IoU、中心线距离、曲率/宽度误差、拓扑一致性。
- 几何合法：零意外自交、边界无折叠、最小净距和越界检测召回率。
- 交互：普通用户在限定时间内完成指定设计，操作数与错误率明显低于 V1。
- 性能：典型桌面/移动设备拖拽时保持可接受帧率；复杂设计的校验、自动修复和导出有明确延迟预算。
- 兼容：V1 订单可打开、渲染、价格计算和导出；迁移前后预览差异可解释。
- 生产：导出尺寸/单位准确，边界闭合，印刷/切割规范通过供应商检查。

### 4. 人工评审

- 产品/设计：是否“像 NessRC 赛道”、是否易理解、模板/生成结果是否有足够多样性。
- 生产/供应商：最小半径、净距、边界、出血、尺寸与文件格式是否可生产。
- 工程：复杂度、测试性、依赖风险、迁移与维护成本。
- 最终选择必须结合定量分数与真实业务评审，不让单一图像相似度决定方案。

## 预期结论形式与决策框架

最终建议至少给出三档方案：

1. **渐进升级**：最大限度复用当前 SVG/React/V1，优先补齐曲线、约束和交互。
2. **推荐主线**：能显著接近真实赛道的 V2 数据模型 + 几何内核 + 双层编辑体验。
3. **高阶路线**：图片导入、程序生成、优化/AI 辅助和生产级自动校验的完整系统。

每档明确：用户价值、支持的赛道类型、核心算法、候选库、自研模块、预计阶段、风险、迁移方式和放弃内容。最终用加权决策矩阵选择推荐主线，建议权重初值：

- 几何保真与合法性 30%

- 可制造性 15%

- 浏览器性能 10%
