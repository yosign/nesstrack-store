# Custom Track 实施路线图

## 推荐顺序

不要先重做 UI 或接 AI。先取得生产真相与历史兼容，再用 6 个关键样本验证“区域/边界网络”内核，达到 gate 后才进入完整编辑器。

## 三档方案

| 方案 | 范围 | 用户价值 | 粗略工作量* | 主要放弃 |
|---|---|---|---:|---|
| 渐进升级 | 冻结 V1；补自交/净距/服务端校验；cubic 中心线；交互加插点/缩放/吸附 | 比当前更顺滑、更少坏单 | 4–6 周 | 仍无法忠实表达多内岛、junction、停车区；不应称“真实赛道编辑器” |
| **推荐主线** | V2 区域/边界网络 + curb/标线 + 可选 driveGraph；简单/高级双层；生产 artifact | 可重建现有主要设计语言，同时普通用户从模板/模块开始 | 10–16 周 | 初期不做任意图片自动导入、全量 OpenDRIVE、AI 最终稿 |
| 高阶路线 | 高质量图片分割/矢量化、参数候选生成、约束优化、AI 意图助手 | 批量模板与更多个性化 | 在主线上再加 6–12+ 周 | 仍保留人工审核；AI 不直接出生产文件 |

\* 假设 1 名熟悉 React/TS 的高级工程师、0.5 名后端、设计/供应商按 gate 及时参与；不是排期承诺。若生产规范或高清源长期缺失，时间无法靠工程并行消除。

## 加权决策

评分 1–5，权重沿用研究计划。分数体现现有样本与当前团队栈，不是通用技术排名。

| 路线 | 几何/合法 30% | 易用 20% | 制造 15% | 工程维护 15% | 性能 10% | 许可证 5% | V1 兼容 5% | 加权 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| V1 中心线样条升级 | 2.5 | 4.0 | 2.5 | 4.0 | 4.5 | 4.5 | 5.0 | 3.45 |
| **区域/边界网络混合** | 4.7 | 4.3 | 4.5 | 3.5 | 4.2 | 4.3 | 4.0 | **4.31** |
| 全量 OpenDRIVE | 4.4 | 2.2 | 4.5 | 1.8 | 2.5 | 3.5 | 2.2 | 3.24 |
| 参数模块/程序生成唯一模式 | 3.5 | 4.5 | 4.0 | 3.4 | 4.2 | 4.5 | 3.5 | 3.88 |
| 图片/AI 直接转生产几何 | 2.0 | 4.0 | 1.5 | 2.5 | 2.5 | 2.0 | 2.0 | 2.45 |

模块生成分数较高，但表达域受模板库限制；应作为推荐主线的简单模式，而不是权威模型。

## 分阶段里程碑

### Phase 0 — 生产与样本 gate（1–2 周）

- 收到 5–10 个高清/矢量源，优先 track-3/15/25/50/90/100。
- 供应商确认：成品格式、单位、裁切/出血、最小特征/间距/线宽/半径、色彩、纹理、Logo、允许触碰/开放边界。
- 产品确认普通买家/专业人员的主次、AI/服务端边界和自定义报价规则。
- 建 20 个正式 ground truth 计划，首批人工标 6 个关键样本。

Gate：未得到生产硬约束时可做编辑 prototype，但不得定义“可制造通过”或开放自动下单。

### Phase 1 — 兼容与订单地基（2–3 周）

- 冻结 V1 fixtures、renderer 与截图；添加 version dispatcher。
- 定义 V2 JSON Schema、canonical quantization/checksum、validation report 和 artifact manifest。
- 外层后台加入自定义设计读取、预览、尺寸/材料报价、下载和人工拒绝状态。
- 把生产 artifact 改为服务端生成/校验；客户端 PNG 降级为即时预览。

Gate：历史 V1 100% 可查看；V2 无法绕过服务端 schema；外层后台能处理模拟自定义订单。

### Phase 2 — 几何内核 spike（3 周）

- 以 track-3/15/25/50/90/100 手工重建 V2 ground truth。
- cubic/arc 自适应展平；Clipper2 TS 整数 boolean/offset；FlattenJS hit/distance/arc。
- region outer/hole、开放 boundary、curb range、marking/symbol、drive junction 最小 renderer。
- Worker 校验：未声明边界交叉、洞关系、最小净距/特征、越界；合法 drive junction 放行。
- 在目标 iPhone/Android 做包体、首次加载、200/1000 控制点 P95。

Gate：6 个样本 topology 100% 一致、IoU ≥ 0.90、压力集召回 ≥ 95%、无崩溃；否则回看 schema/内核，不进入 UI 扩张。

### Phase 3 — V2 MVP 编辑体验（4–6 周）

简单模式：模板/模块、整体变形、风格/复杂度、镜像/旋转、合法候选、多级错误提示。高级模式：边界节点与切线、区域/洞、curb 区间、标线、junction/route 检查。共同能力：zoom/pan、吸附、段插点、框选/多选、撤销事务、局部修复预览、尺寸/报价实时反馈。

Gate：至少 10 名目标用户，任务成功率 ≥ 80%，中位耗时比 V1 低 ≥ 30%；正式 20 样本 topology 100%，轮廓 IoU ≥ 0.95 或达到供应商容差。

### Phase 4 — 生产上线（3–5 周）

- canonical SVG + 供应商要求的 PDF/高分辨率 PNG；DXF 仅在确认需要后做。
- artifact checksum、renderer/validator version、审计日志、失败回滚。
- 灰度开关：V1 旧下单、V2 内部账号、V2 小流量、全面开放。
- 供应商对 10 个导出文件签字验收；模拟退款/拒单/重做流程。

Gate：尺寸/拓扑/最小特征全通过；外层后台无自定义订单盲区；生产文件可回溯到订单 JSON 和 kernel 版本。

### Phase 5 — 高阶增强（每项独立 gate）

1. 离线模板管线：区域分割 → VTracer/轮廓 → 人工语义分层 → V2 校验。
2. 参数生成：模块/模板变形生成 8–20 个合法候选，确定性 seed，先硬过滤再按多样性排序。
3. 优化：拖拽后局部投影/排斥在 Worker；全局 differential evolution/CMA-ES 放服务端。
4. AI：仅把自然语言变成模板/参数操作，或产生待审核草稿；解析 SVG 白名单并重建 V2，禁止直接上传任意生成 SVG 到生产。

## 团队边界

- 前端/几何：domain commands、renderer、worker、interaction、fixtures。
- 后端：权威校验、artifact、订单契约、权限与审计。
- 设计：6/20 个 ground truth、模板/模块、错误反馈语言、用户测试。
- 供应商：硬约束与文件签收；没有其确认不能替工程团队定义容差。

## 风险与缓解

| 风险 | 概率/影响 | 缓解 |
|---|---|---|
| 缩略图误导模型 | 高/高 | Phase 0 强制高清源；缩略图只用于拓扑 |
| “自交”规则误杀合法 junction | 高/高 | boundary 和 driveGraph 分开；只禁止未声明的边界问题 |
| TS port 退化几何 bug | 中/高 | 固定版本、真实/随机压力集、与另一 oracle 交叉、服务端重验 |
| 未来 renderer 改变历史订单 | 中/高 | 不可变 artifact + renderer version + V1 冻结 |
| 外层后台继续忽略自定义订单 | 高/高 | Phase 1 先打通，再开放 V2 下单 |
| 简单模式仍太专业 | 中/高 | 默认模板/模块/候选；高级控制渐进展开；实测 gate |
| AI 输出恶意/超复杂 SVG | 中/高 | sandbox、primitive 白名单、复杂度上限、重建 V2、服务端校验 |
| 许可证/维护变化 | 低/中 | SBOM、lockfile、许可证复核；依赖接口薄封装、可替换 |

## 下一步最小行动

1. 约供应商和产品做 60 分钟规范会，回答报告未决项。
2. 索取 6 个关键样本的高清源/生产文件并建立 ground truth。
3. 只开一个隔离 `region-kernel-spike`，不碰生产编辑器；用本报告 gate 决定是否进入 Phase 1/2。
